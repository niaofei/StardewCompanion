# 操作反馈与游戏事件

普通决策的最新字段布局见 [输入消息架构](输入消息架构.md)：`dailyPlan` 已归入 `agentState`，最近反馈归入 `agentState.lastAction`，阻塞归入 `agentState.blocked`，待送达事件归入 `recentEvents`。下述送达、存储与原生事件机制继续使用。

LLM 输入包含三种不同的信息，均由游戏观察与真实执行结果产生：

- `dailyPlan`：当前目标、接下来做什么、成功完成的游戏进度。失败不记为成果。
- `actionFeedback`：最近任务或计划的实际结果、部分完成内容、原始失败原因、未执行步骤与仍未解决的阻塞。`accepted` 只表示开始执行。
- `gameEvents`：尚未成功送达决策模型的游戏事件。当前支持新邮件、换日、原版晕倒、背包容量变化和操作中断。

同一目标的重复阻塞合并计数。满包阻塞在释放空间、目标已不存在或原版确认可以接收目标物品后解除；其他阻塞在相关观察状态变化后重新核验。重复目标拦截保留原始失败原因。某一步失败后，后续步骤仍停止执行，由模型根据反馈重新规划，包括处理未执行的返家和睡觉步骤。没有固定时间或体力阈值接管玩家决策。

Mod 在各存档与角色独立的本地事件文件中保存事件，直到 Core 落盘并确认接收；断线期间继续累计。Core 将待送达、已送达与去重信息保存在该存档角色的数据库设置中。模型请求成功返回且上下文有效后才确认送达，请求失败或取消不会确认。季节维护不消耗普通决策的待送达事件。暂停不因事件自动启动决策。

`pass_out` 来自原版 `Farmer.passOutFromTired` 的调用；正常睡觉依据原版接受的 `Sleep_Yes` 与随后换日关联。无法确认的换日原因标为 `unknown`。

当前状态另提供背包容量、空格数、采集物是否可装入和未读邮件状态。`read_mailbox` 返回原版未读邮件的正文及附件模板，属于只读查询，不改变原版已读状态或领取附件。模板中的动态变量和附件指令保留，附件实际能否领取在没有原版界面证据时标为未知。

每次请求在发送前记录完整 JSON 请求体，包含所有工具轮次和失败后重试；`requestId` 关联决策与模型响应。不记录 HTTP Authorization。导出 Markdown 仅改变 JSON 排版，不改写字段内容。

桌面操作流窗口提供“反馈 · 阻塞 · 事件”页，显示最近反馈、未解决阻塞、待送达及最近已送达事件。反馈版本与已送达版本可用于判断新结果是否已经送入模型。

验证命令：

```powershell
.tools\dotnet\dotnet.exe build StardewCompanion.slnx -c Release --no-restore
.tools\dotnet\dotnet.exe tools\CoreChecks\bin\Release\net10.0\CoreChecks.dll D:\code\sw --awareness
.tools\dotnet\dotnet.exe tools\CoreChecks\bin\Release\net10.0\CoreChecks.dll D:\code\sw
```

`--awareness` 对真实请求体验证满包失败、未执行步骤、重复拦截、阻塞解除、请求失败后事件保留、暂停/恢复、重启去重、跨存档隔离和预算保护。独立实机实验场的 `awareness` / `awareness_passout` 场景用于验证满包黄水仙、新邮件和原版晕倒；这些场景会布置测试条件，不能算自主开荒成绩。
