# 短计划与滚动贪心

本轮改进以 DeepSeek 自主选择为核心，不内置每日开荒路线或工作量。

- 模型通过 execute_plan 提交1到8步，步骤显式声明技能和参数。参数结构复用同一份技能定义；种子必须指定。游戏接口保留单技能兼容，模型界面只展示一个计划执行入口。
- 本地逐步重新检查身份、权限、材料和游戏状态，等待真实终态及更新后的观察才执行下一步。失败、部分完成、暂停、取消或换会话时停止余下步骤。睡觉只能在最后一步。
- 继续工作、返家、睡觉及是否接受晕倒损失完全交给LLM。已删除本地低体力/低生命接管、22点收工和技能20%体力截止，不会自行返家、睡觉或因这些阈值拒绝劳动。原版疲劳、晕倒、扣款及自然换日仍照常发生；自然换日会终止旧日工作步骤并让模型按新观察重新选择。
- 每次观察提供decisionFacts：体力/疲劳、原版-15体力与凌晨2点晕倒条件、当前地点扣款上界、次日恢复影响、箱子材料缺口、礼包位置及附近枝条。数字估算明确标注；不是停工指令。
- 每步回执提供开始/结束体力、净消耗、生命变化和游戏时间。clear_area必须声明targetType，收木材可只选择twig，避免混合清障的无关消耗；制箱失败明确区分配方未知与木材缺口。
- 计划标识按存档、角色、会话保存，重复提交不会重复操作。程序重启不自动恢复未完成计划。
- 取消统一20秒空闲。计划完成后约200ms调度下一轮，执行中不询问模型；无事可做时显式等待，状态变化提前唤醒。请求失败仍保留退避，防止请求风暴。
- 玩家原始指令按存档角色单独持久保存，每轮注入，不受20条聊天限制。历史版本自动从玩家聊天恢复；明确取消后清空当前指令，模型不能修改它。
- 模型自述不再作为事实聊天历史反复注入；上下文以当前世界、持久指令、上一计划回执和最近查询为主。日志仍记录公开模型回复。
- 候选先保护已投入作物，再处理成熟收获、附近采集；距离使用明确标注的曼哈顿估算，不冒充可达路径或确定收益。模型结合短依赖链、体力和路程决定具体工作，执行器核验可达性。
- 回执明确区分 requestedTarget、playerStart/playerEnd、affectedTiles；种植不包含锄地。播种缺少耕地、锄地存在阻碍分别返回明确原因。批量 inspect_targets 支持一次检查32格。

检查覆盖：8步一次模型选择、步骤间不调用模型、完成后及时决策、失败停止余下操作、暂停中断、重复计划去重、缺参拒绝、目标跨聊天截断/重启保留、存档隔离和贪心候选优先级。完整统一检查及真实 DeepSeek 工具兼容性需与实机结果分别报告。

运行新档自主五日测试：

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/start-solo-five-days.ps1 -Autonomous
~~~

启动只发送一次总目标并恢复，随后由 DeepSeek 选择计划。监控仅读取日期和运行状态，第五夜保存到第六天后自动暂停；人工中止必须单独记录。普通联机开荒能力仍未开放，挖矿钓鱼等仍禁止。
