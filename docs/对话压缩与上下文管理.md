# 对话压缩与上下文管理

## 季节与每日计划（季节计划进度维护已接入）

季节计划独立存储，目标、约束、成功条件及季节字段在当季锁定；每日睡觉换日后只允许追加上一日成功工具回执支持的进度。季节切换后，先保存上一季进度与结果核验，再创建新季计划；程序校验进度更新和日历季节，阻止同季改写固定字段。季末 review 与完整季节计划归档在本地。

普通每日决策只投影 `dailyPlan.goal`、`dailyPlan.next`（接下来做什么）和 `dailyPlan.done`（成功回执）。之前的计划归档、失败工具调用及批次决策历史不再逐轮发送；当前世界观察、玩家约束、季节计划、必要项目记忆仍保留。睡后季节维护是独立轻量请求，只发送玩家目标、当前季节/日期、锁定季节计划和上一日成功回执，工具目录仅开放进度更新与季节计划创建。

2026-10-30：已接入模型请求路径。压缩在本地完成，不为摘要增加模型请求，也不修改 SQLite 内保存的完整计划、记忆、回执和日志。

普通决策保留用户指令原文（只合并完全相同的重复指令）、当前观察与弹窗、当前每日目标、下一步待办、最近六条成功执行回执、季节计划及必要记忆。失败、取消和程序决策批次历史不再逐轮回传。每日 plan 主要提供 `dailyPlan.next` 和 `dailyPlan.done`；批次完成不自动代表长期目标已完成。

成功回执保留实际物品变化、体力与时间消耗、原目标和业务结果正文。处理格和剩余掉落只在默认摘要中列出总数及四项样本，明确标记 sampleOnly；完整坐标可分页读取。邮件、对话正文和当前弹窗不会按处理格规则裁切。失效的跨日查询缓存不进入新一天的上下文。

`lastPlan` 与最近回执中的相同任务 ID 只发送一次。项目和工作箱如果已经单独投影，不再在记忆中重复发送；非工作箱地点笔记和旧版本的非结构化项目仍保留。`observe` 成功后会刷新本轮唯一的当前观察，工具回复只告知已刷新，避免再携带一整份世界。

中文按自然文本编码；回执 Details 等已序列化 JSON 会先解析，避免在模型消息中重复出现多层 JSON 转义。较大的同构观察数组用 `columns`、`rows` 表格无损表示。`missing` 中的 `[行,列]` 从零开始，代表原观察没有该字段，区别于实际的 null。

默认主上下文软预算为 32,000 字符，不是精确 token 数，也不包含系统提示、工具 schema 及后续工具消息。超出时逐步移除旧完成索引、候选建议、查询缓存、较早目标索引和普通经验，记录省略项。用户要求、当前观察/弹窗、当前目标、实际反馈和用户约定不直接截断；仍超预算时明确报告 `overBudget`。

## 按需读取历史

模型工具 `read_context_history` 仅查询当前存档与角色的数据，参数为 `source`、`id`、`offset`、`limit`；`offset >= 0`，每页 `limit` 为 1–8。

| source | id | 返回内容 |
| --- | --- | --- |
| plans | 空字符串 | 分页计划索引、状态和待办 |
| plans | 计划 ID | 目标、依据、假设、完成条件、原步骤及分页执行回执 |
| memory | 空字符串 | 分页记忆索引和明确标记的文本预览 |
| memory | 数字记忆 ID 或项目 GUID | 原文；项目的历史执行证据按页读取 |
| receipts | 任务 ID | 实际回执和分页处理格、剩余掉落 |

历史完成状态与现存世界事实有区别，返回的历史证据需要新观察核对。记忆历史查询直接分页读取数据库，不受普通工作记忆最近五百条的窗口限制。
