# LLM 输入消息架构

普通决策由一个简短 system 消息和一个结构化 user 消息开始。system 采用《架构.md》的七条工作原则；技能参数、实际失败原因和当前游戏状态分别通过工具定义、执行反馈和动态输入提供。同一次决策中的工具调用保留 API 所需的 assistant/tool 消息。

动态输入固定为八部分：

| 字段 | 来源与含义 |
| --- | --- |
| `trigger` | 玩家消息、目标更新、任务结果、游戏事件、换日或等待条件变化 |
| `playerGoal` | 独立维护的原始目标、完成条件、优先级、限制、行动范围和版本 |
| `conversation` | 尚未送达的新消息，以及等待玩家回答的问题 |
| `agentState` | 持续工作目标、依据、下一步、实际成果、当前阻塞和最近行动结果 |
| `world` | 当前地点有效观察、背包容量、时间风险、邮箱及与行动有关的世界内容 |
| `recentEvents` | 待送达游戏事件，以及最近操作结果的简要通知 |
| `relevantMemories` | 最多三条相关工作经验，附来源 |
| `decisionScope` | 与实际工具 Schema 一致的技能、查询和工具名称 |

执行批次结束后，持续工作目标与后续待办继续保留。`save_plan` 用于更新工作目标；`execute_plan` 提交服务于该目标的执行批次。成果由 Core 根据原生回执维护，`accepted` 表示提交执行。当前输入最多携带十六项相关成果和八项当前待办，不重放历日批次档案或任务数量统计。

## 长期目标与聊天

操作流窗口中的“长期目标”页提供独立编辑入口。普通聊天进入对话队列，不自动写入长期目标。旧版 `player_instructions` 的原始条目保留在 SQLite，并迁移为目标原文。

- `GET /agent/goal`：读取当前存档与角色的目标、状态及版本。
- `POST /agent/goal`：写入 `objective`、`completionCondition`、`priorities`、`restrictions`、`autonomy`、`disabledSkills`。可带 `expectedVersion` 检查编辑冲突。
- `GET /agent/input`：读取最近生成的八部分输入，前端提供对应预览页。

更新目标会停止当前批次，并清理旧工作安排，实际成果仍保留。取消工作会取消当前目标并清空待发送对话。消息在模型返回有效响应且会话未变化后确认送达；HTTP 失败、取消或空响应不会丢弃未送达消息。跨存档与角色隔离保存。

## 世界与工具

Core 保留完整原始观察；每次输入提供当前地点的相关内容。区域列表有数量与截取标识，需要更多细节时可查询。农舍中的农场汇总不携带作物坐标，明确标记 `unknown_from_current_location`。旧查询附地点、日期和观察版本，当前原生观察优先。

矿洞相关能力关闭，其余功能明确开放，不以“待验证”或验收证据作为功能入口条件。Core 按当前工作、观察和明确限制缩小工具 Schema；`list_capabilities` 可以展开其他已开放功能，无独立的工具选择模型调用。选定执行批次后，下一轮恢复规则筛选并保留该批次涉及的技能。参数约束和实际执行权限仍由本地执行器处理。

最近失败保存在 `agentState.lastAction`，未解决原因保存在 `agentState.blocked`。`recentEvents` 引用该结果，不重复塞入整份回执。事件保持此前的持久化、去重和送达确认机制；季节维护继续独立执行，不消费普通行动决策的待送达事件。

SQLite 保存目标、工作状态、聊天、消息队列与诊断档案，原始请求日志继续保留。`read_context_history(source="diagnostics")` 可分页查询诊断索引，指定记录 ID 可读原文。可选经验优先在超预算时移出本轮输入；当前目标、未送达消息与事件、当前阻塞保留，并通过诊断事件报告预算溢出。

本次按要求只做编译检查，不运行自动化测试、实机短测或十天测试。测试启动器已改为使用独立目标接口，等待后续明确启动。
