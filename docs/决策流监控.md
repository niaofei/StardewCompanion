# LLM 自主流程与决策监控

独立只读窗口：

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/start-decision-monitor.ps1
~~~

默认连接当前solo5测试，也可用-SessionFile指定其他会话文件。窗口每秒显示游戏日期、时间、地点、体力生命、模型请求、公开回复、计划、技能参数、实际回执和错误；选中一行可看完整详情并复制。参数和回执的嵌套JSON会展开，计数对应本次载入事件；完整历史以磁盘日志为准。

监控只执行读取请求，不启动新的桥接服务、不派发任务；关闭窗口不暂停游戏。当前测试仍由DeepSeek自主执行。

桌面端和启用 `--agent` 的诊断服务均提供认证的回环接口。模型提示明确禁止钓鱼、挖矿、战斗等尚未实现的能力，工具目录也不开放这些动作。

## 启动与查看

从仓库根目录运行，默认读取 `.local/model.credentials.json` 中的本机加密模型配置：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/start-agent.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tools/watch-decisions.ps1
```

服务从暂停状态启动。AI 加入后，可通过桌面端发送总体目标并继续，或使用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/invoke-agent.ps1 -Operation message -Text '暂不能挖矿钓鱼。观察后自主完成已授权的农务、采集、工作箱归仓，再返家睡觉。'
powershell -NoProfile -ExecutionPolicy Bypass -File tools/invoke-agent.ps1 -Operation resume
powershell -NoProfile -ExecutionPolicy Bypass -File tools/invoke-agent.ps1 -Operation state
powershell -NoProfile -ExecutionPolicy Bypass -File tools/invoke-agent.ps1 -Operation pause
```

桌面程序的“诊断”页同时显示最近 30 条决策事件。日志写入本次数据目录中的 `decisions.jsonl`，不写入模型密钥或请求认证头。只记录模型公开回复和工具调用，不记录模型服务可能返回的内部推理字段。

## 接口

所有接口只监听回环地址并要求 `Authorization: Bearer <本机会话令牌>`。脚本从 `session.json` 读取令牌，无需将其放入 URL。

| 接口 | 用途 |
| --- | --- |
| `GET /agent/state` | Agent 状态、是否启用、是否等待模型、待答问题和当前观察 |
| `GET /agent/events?after=0&limit=200` | 按游标读取决策事件；内存保留最近 1000 条，完整记录查看 JSONL |
| `POST /agent/message` | `{ "text": "总体目标" }`，发送玩家指令 |
| `POST /agent/resume`、`pause`、`cancel` | 控制 Agent 及模组；与仅控制模组的旧 `/resume` 等诊断接口不同 |
| `POST /agent/chest` | 操作者绑定当前地图的工作箱，参数为 `name,x,y,allowedIds,protectedIds`；模型不能调用此接口授权自己 |

事件有 `Sequence`、UTC 时间 `At`、存档角色 `Scope`、游戏会话 `Session`、规划 ID `DecisionId`、事件类型 `Kind` 和数据 `Data`。Sequence 是本次服务进程内的游标，重启监控脚本会重新读取当前进程。规划 ID 关联模型选择、任务派发和后续回执。

主要事件：`decision_context` 保存决策时的实际观察、近期回执和相关记忆；`model_request` 与 `model_reply` 保存模型名称、公开回复、工具选择、耗时和用量；`permission_allowed`、`tool_rejected` 保存授权或拒绝结果；`task_dispatch` 标明任务来源；`task_result` 保存 accepted、进度和实际终态。短计划有plan_started和plan_finished。当前版本已移除本地体力/时间安全接管；旧日志中的local_safety属于历史行为。

`accepted` 只表示已接单，不能据此声称工作完成。完成数量需核对终态回执中的 `Completed`、`Details` 的物品明细和新观察。真人房主的上床与换日仍遵循原版联机规则。
